# Synthetic Document Generator for Payment & Banking Systems

A comprehensive Python-based tool for generating highly realistic, synthetic financial documents in multiple formats. Perfect for building document libraries and testing payment/banking systems.

## ⚠️ Important Notice

**All generated documents include a mandatory watermark:**

> *This synthetic document is generated by Rahul Raj for testing purpose.*

This ensures that no document can be mistaken for real financial data. All data is **100% synthetic** and suitable for testing purposes only.

---

## Features

### Document Types

1. **Bank Account Statements**
   - Checking and savings accounts
   - Transaction history with running balances
   - Summary sections (deposits, withdrawals, fees, interest)
   - Realistic transaction descriptions

2. **Credit Card Statements**
   - Purchase history with merchant details
   - Payment summaries and due dates
   - Interest and fee calculations
   - Credit limit and available credit

3. **Payment / Remittance Advice**
   - Invoice references and line items
   - Payment methods and settlement dates
   - Tax and discount calculations

4. **Terms & Conditions / Agreements**
   - Multi-page legal-style documents
   - Realistic English content (no lorem ipsum)
   - Payment-related clauses and sections

5. **Notifications / Letters**
   - Overdraft notices
   - Payment confirmations
   - Chargeback notifications
   - KYC reminders
   - Address change confirmations

6. **Emails (.msg / .eml)**
   - Outlook-compatible messages
   - HTML formatted bodies
   - Statement notifications
   - Payment alerts
   - Security notifications

### Output Formats

- **PDF** (`.pdf`) - Professional documents with proper formatting
- **Microsoft Word** (`.docx`) - Editable Word documents
- **Microsoft Excel** (`.xlsx`) - Spreadsheet format for statements
- **Outlook Email** (`.msg`) - Outlook-compatible email messages
- **Standard Email** (`.eml`) - RFC 5322 compliant email format
- **OpenDocument Text** (`.odt`) - LibreOffice/OpenOffice compatible
- **Images** (`.jpeg`, `.jpg`, `.png`) - Rendered document images

### Key Capabilities

- **Realistic Synthetic Data**: Uses Faker library with domain-aware logic
- **No Placeholder Text**: No lorem ipsum or trivial sequences like "12345678"
- **USA-Style Formatting**: Dates, currency, addresses in US format
- **Coherent Data**: Running balances, date-ordered transactions, realistic amounts
- **Interactive CLI**: User-friendly menu system with rich formatting
- **Size-Based Generation**: Generate documents until a target size is reached
- **Configurable**: YAML configuration file for defaults
- **Modular Architecture**: Easy to extend with new document types or formats

## Installation

### Prerequisites

- Python 3.8 or higher

1. **Clone or download this repository**

```bash
cd documents-tool
```

2. **Create a virtual environment** (recommended)

```bash
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
```

```bash

```

That's it! You're ready to generate documents.

## Usage Examples

### Example 1: Generate Mixed Documents with No Size Constraint

```bash
python generate_docs.py
```

Then select:
- Document types: `A` (all)
- Formats for each: `A` (all)
- Output directory: `./output`
- Mode: `1` (count-based)
- Count: `10`

This will generate 10 documents for each type/format combination.

### Example 2: Generate Documents Until ~10-15 MB

```bash
python generate_docs.py
```

Then select:
- Document types: `1,2` (bank and credit card statements)
- Formats: `1` (PDF only)
- Output directory: `./my_docs`
- Mode: `2` (size-based)
- Target size: `12MB`

The tool will generate documents until the total size reaches approximately 12MB.

### Example 3: Using Custom Configuration

1. Create a custom config file `my_config.yaml`:

```yaml
output:
  directory: "./custom_output"

generation:
  random_seed: 42  # For reproducible generation
  default_count: 20

documents:
  bank_statement:
    num_transactions: 50  # More transactions per statement

data:
  locale: "en_US"
```

2. Run with custom config:

```bash
python generate_docs.py --config my_config.yaml
```

## Configuration

The tool uses a YAML configuration file located at `config/default_config.yaml`. You can customize:

### General Settings

```yaml
output:
  directory: "./output"  # Where to save generated files
  filename_pattern: "{doc_type}_{timestamp}_{counter}"

generation:
  random_seed: null  # Set to integer for reproducible output
  default_count: 10
  max_transactions_per_statement: 40
  min_transactions_per_statement: 15
```

### Document-Specific Settings

```yaml
documents:
  bank_statement:
    num_transactions: 30  # Override default
    opening_balance: 5000.00  # Set specific balance

  credit_card_statement:
    previous_balance: 1500.00

  terms_conditions:
    num_sections: 10
```

### Size Estimation

```yaml
size_estimation:
  tolerance: 0.15  # ±15% tolerance for size-based generation
  max_iterations: 100
```

## Extending the Tool

### Adding a New Document Type

1. Create a new generator in `src/generators/`:

```python
from .base import BaseDocumentGenerator

class MyDocumentGenerator(BaseDocumentGenerator):
    def get_document_type(self) -> str:
        return 'my_document'

    def generate_content(self) -> dict:
        # Generate document content
        return {
            'title': 'My Document',
            # ... your content
        }

    def get_supported_formats(self) -> list:
        return ['pdf', 'docx']
```

2. Register it in `src/generators/__init__.py`:

```python
from .my_document import MyDocumentGenerator

GENERATOR_REGISTRY = {
    # ... existing
    'my_document': MyDocumentGenerator,
}
```

3. Add format support in `src/formats/__init__.py`:

```python
DOCUMENT_FORMAT_SUPPORT = {
    # ... existing
    'my_document': ['pdf', 'docx', 'xlsx'],
}
```

### Adding a New Output Format

1. Create a new writer in `src/formats/`:

```python
class MyFormatWriter:
    def __init__(self, filepath: str):
        self.filepath = filepath

    def write(self, content: dict, doc_type: str):
        # Write content to your format
        pass
```

2. Register it in `src/formats/__init__.py`:

```python
WRITER_REGISTRY = {
    # ... existing
    'myformat': MyFormatWriter,
}
```

## Troubleshooting

### Issue: ImportError for a library

**Solution**: Make sure you've installed all dependencies:

```bash
pip install -r requirements.txt
```

### Issue: Fonts not found for image generation

**Solution**: The image writer tries to use DejaVu fonts. If not available, it falls back to default fonts. To get better-looking images, install DejaVu fonts:

- **Ubuntu/Debian**: `sudo apt-get install fonts-dejavu`
- **macOS**: Fonts are usually pre-installed
- **Windows**: Download and install DejaVu fonts

### Issue: Generated files are empty or corrupt

**Solution**: Check that:
1. You have write permissions to the output directory
2. There's sufficient disk space
3. All dependencies are correctly installed

## Limitations

1. **MSG Format**: The MSG writer creates EML-compatible files saved with `.msg` extension. For true Outlook MSG format on non-Windows systems, external tools may be needed.

2. **Size Estimation**: File size estimates are approximate (±20%) and may vary based on content.

3. **Performance**: Generating thousands of documents may take several minutes depending on system performance.

## FAQ

**Q: Can I use this for production data?**
A: **NO**. This tool generates synthetic test data only. All documents are clearly watermarked as synthetic.

**Q: How realistic is the generated data?**
A: Very realistic. We use Faker with domain-specific logic for banking data. However, account numbers, card numbers, and all personal information are completely synthetic.

**Q: Can I remove the watermark?**
A: The watermark is mandatory and hardcoded to ensure generated documents are never confused with real data.

**Q: What's the maximum number of documents I can generate?**
A: There's no hard limit, but generating thousands of documents may take significant time and disk space.

**Q: Can I customize the document content?**
A: Yes, through the configuration file or by extending the generator classes.
